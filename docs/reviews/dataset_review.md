## RRF / Reranker 实验的关键缺口

现有原文单元仅 22 个，每个 79–132 字；这不是正式 Chunk 数量，但说明当前资料规模很小。默认 N=50、M=50 下，可能无法触发有意义的候选截断，必须在实际分块后确认。

应补语义相近且有真实差异的候选资料，并设计满足“候选并集数量大于 M”的压力案例，记录实际 N/M/K、去重数和被截断的相关证据。小窗口可用于功能测试，不能由此推导默认窗口下的质量/性能收益；B3a/B3b 的实验参数必须固定并共同报告。

## 与 v1.2 的数据兼容性

现有 EvalCase 的 GoldAnchor 结构仍适用，无需因移除 Evidence 实体而重写全部题目。Source ID 是请求内动态标识，不能提前写死为标准答案里的 S1/S2；运行后通过 Source Map 回到 Chunk 和原文锚点评分。

当前校验器专用于 synthetic-v1：题数 20、题型配额和仅支持 DOCX/XLSX 的规则均写死，返回 human_review 也固定为 pending。新增数据集或开始登记人工复核时，需要同步扩展校验器，按实际标注汇总状态；不应只把 20 改成更大的数字。新数据宜另建目录，保留当前夹具可复现性。

补充顺序：先修标签与协议，再补干扰语料、证据组合及独立验证数据；随后按解析器和生成模块进度扩展。现有已读开发题不能简单补到 120 题后改名为冻结测试集。
